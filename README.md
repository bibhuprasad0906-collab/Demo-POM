# Selenium Pytest Automation Framework\n\n## Overview\n\nThis is a production-ready, enterprise-grade Selenium pytest automation framework for testing authentication and login functionality across Web and Mobile platforms. The framework implements the Page Object Model (POM) design pattern, robust error handling, comprehensive logging, and full traceability to user stories.\n\n## Features\n\n- **Page Object Model (POM)**: Clean separation of test logic and page interactions\n- **Robust Error Handling**: Custom exceptions and comprehensive error logging\n- **Data-Driven Testing**: CSV-based test data parametrization\n- **Cross-Browser Support**: Chrome and Firefox with headless mode\n- **Environment Configuration**: Flexible configuration via environment variables\n- **Traceability**: Full mapping between test cases and user stories\n- **CI/CD Ready**: GitHub Actions workflow included\n- **Accessibility Testing**: WCAG 2.1 AA compliance checks\n- **Security**: No plain-text credential storage, audit-compliant logging\n\n## Project Structure\n\n```\n.\n├── .github/\n│   └── workflows/\n│       └── ci.yml                 # CI/CD pipeline configuration\n├── features/\n│   └── login.feature              # Gherkin scenarios for all test cases\n├── src/\n│   ├── pages/\n│   │   ├── base_page.py          # Abstract base page with safe Selenium wrappers\n│   │   └── login_page.py         # Login page object with robust error handling\n│   └── utils/\n│       ├── config.py              # Configuration loader from environment\n│       ├── driver_factory.py     # WebDriver instantiation\n│       └── exceptions.py         # Custom exceptions\n├── tests/\n│   ├── data/\n│   │   └── login.csv             # Test data for parametrized tests\n│   ├── conftest.py               # Pytest fixtures and parametrization\n│   └── test_login.py             # Parametrized test suite\n├── traceability.json             # Story ID to test method mapping\n├── requirements.txt              # Python dependencies\n└── README.md                     # This file\n```\n\n## Test Coverage\n\nThe framework covers 12 authentication test scenarios:\n\n- **AUTH-001**: Login with valid credentials on Web\n- **AUTH-002**: Login with valid credentials on Mobile\n- **AUTH-003**: Login with invalid credentials on Web\n- **AUTH-004**: Login with invalid credentials on Mobile\n- **AUTH-005**: Account lockout after repeated failed attempts on Web\n- **AUTH-006**: Account lockout after repeated failed attempts on Mobile\n- **AUTH-007**: Locked user receives lockout notification on Web\n- **AUTH-008**: Locked user receives lockout notification on Mobile\n- **AUTH-009**: Password visibility toggle on Web\n- **AUTH-010**: Password visibility toggle on Mobile\n- **AUTH-011**: Audit login attempts for compliance\n- **AUTH-012**: Accessibility compliance for login forms\n\n## Prerequisites\n\n- Python 3.8 or higher\n- pip (Python package manager)\n- ChromeDriver (for Chrome browser testing)\n- GeckoDriver (for Firefox browser testing)\n- Git\n\n## Installation\n\n1. **Clone the repository**:\n   ```bash\n   git clone https://github.com/bibhuprasad0906-collab/Demo-POM.git\n   cd Demo-POM\n   ```\n\n2. **Create a virtual environment** (recommended):\n   ```bash\n   python -m venv venv\n   source venv/bin/activate  # On Windows: venv\\Scripts\\activate\n   ```\n\n3. **Install dependencies**:\n   ```bash\n   pip install -r requirements.txt\n   ```\n\n4. **Install browser drivers**:\n   - **ChromeDriver**: Download from https://chromedriver.chromium.org/ and add to PATH\n   - **GeckoDriver**: Download from https://github.com/mozilla/geckodriver/releases and add to PATH\n\n## Configuration\n\nThe framework uses environment variables for configuration. Set the following variables before running tests:\n\n- **BASE_URL**: Base URL of the application (default: `http://localhost:8080`)\n- **BROWSER**: Browser to use (`chrome` or `firefox`, default: `chrome`)\n- **HEADLESS**: Run in headless mode (`true` or `false`, default: `true`)\n- **TIMEOUT**: Default timeout in seconds (default: `10`)\n\n### Example Configuration\n\n**Linux/Mac**:\n```bash\nexport BASE_URL=\"https://example.com\"\nexport BROWSER=\"chrome\"\nexport HEADLESS=\"true\"\nexport TIMEOUT=\"15\"\n```\n\n**Windows**:\n```cmd\nset BASE_URL=https://example.com\nset BROWSER=chrome\nset HEADLESS=true\nset TIMEOUT=15\n```\n\n## Running Tests\n\n### Run All Tests\n```bash\npytest\n```\n\n### Run Specific Test by Story ID\n```bash\npytest -m story=\"AUTH-001\"\n```\n\n### Run Tests with Verbose Output\n```bash\npytest -v\n```\n\n### Run Tests in Parallel (requires pytest-xdist)\n```bash\npip install pytest-xdist\npytest -n auto\n```\n\n### Generate HTML Report (requires pytest-html)\n```bash\npip install pytest-html\npytest --html=report.html --self-contained-html\n```\n\n## Test Data Management\n\nTest data is stored in `tests/data/login.csv`. The CSV file contains the following columns:\n\n- **scenario**: Test scenario ID (e.g., AUTH-001)\n- **username**: Username for login\n- **password**: Password for login\n- **expected**: Expected result (success, fail, lockout, locked)\n- **attempts**: Number of login attempts (for lockout scenarios)\n\nTo add new test data, simply add rows to the CSV file following the same format.\n\n## Traceability\n\nThe `traceability.json` file maps user story IDs to test method names, ensuring full traceability between requirements and test implementation. This file is automatically maintained and should be updated whenever new tests are added.\n\n## CI/CD Integration\n\nThe framework includes a GitHub Actions workflow (`.github/workflows/ci.yml`) that automatically runs tests on every push and pull request to the main branch. The workflow:\n\n1. Sets up Python 3.10\n2. Installs dependencies\n3. Runs tests in headless Chrome mode\n4. Fails fast on first error\n\n## Troubleshooting\n\n### Driver Errors\n- **Issue**: WebDriver not found or version mismatch\n- **Solution**: Ensure ChromeDriver/GeckoDriver is installed and matches your browser version. Add driver to system PATH.\n\n### Element Not Found Errors\n- **Issue**: Test fails with ElementNotFoundError\n- **Solution**: Update locators in `src/pages/login_page.py` to match actual UI elements. Verify element IDs, classes, or XPath expressions.\n\n### Data Mismatch Errors\n- **Issue**: Test skipped or data not loaded\n- **Solution**: Validate CSV file format and ensure scenario IDs match test expectations.\n\n### CI/CD Failures\n- **Issue**: Tests pass locally but fail in CI\n- **Solution**: Check environment variables in workflow file. Ensure headless mode is enabled. Verify driver installation in CI environment.\n\n## Best Practices\n\n1. **Keep Page Objects Clean**: Only include page-specific logic in page objects\n2. **Use Explicit Waits**: Always use WebDriverWait for dynamic elements\n3. **Maintain Test Data**: Keep CSV files up-to-date with current test scenarios\n4. **Update Traceability**: Update `traceability.json` when adding new tests\n5. **Run Tests Regularly**: Schedule nightly CI runs for regression testing\n6. **Review Logs**: Check logs for warnings and performance issues\n7. **Secure Credentials**: Never commit credentials to version control\n\n## Future Enhancements\n\n- **Allure Reporting**: Integrate Allure for rich test reports\n- **Backend Validation**: Add API tests for audit log verification\n- **Extended Accessibility**: Full WCAG 2.1 AA coverage with axe-core\n- **Performance Testing**: Add response time assertions and monitoring\n- **Code Coverage**: Track test coverage with pytest-cov\n- **Docker Support**: Containerize tests for consistent execution\n\n## Contributing\n\nContributions are welcome!
